# Novalist

> 当前发布版本：`v2.0.8-beta`。本版本为 Windows x64 便携包加入事务式自动安装更新、启动自检与失败回滚，属于公开预览版；请在真实创作项目中使用前先完成一次本机 DSh 实测并保留独立备份。

Novalist 是一款面向长篇小说创作的本地桌面工具，使用 PySide6 构建，并可通过 `dsh` 的 `headless` 模式调用 DeepSeek Harness 完成章节扩写、一致性检查、章节摘要和故事状态更新。

> **第三方项目声明**：Novalist 是独立开发的第三方开源工具，不是 DeepSeek 或 DeepSeek Harness 的官方产品，与其不存在隶属、合作、授权、认证或背书关系。“DeepSeek Harness”仅用于说明兼容性和所依赖的外部工具。

## 项目定位

- 独立桌面应用，而不是加载到 Harness Cordis 插件树中的原生插件
- 小说、设定和记忆文件默认保存在本地 Markdown/JSON 文件中
- Novalist 不直接接收或保存 DeepSeek API 密钥；凭据和模型连接由用户安装的 `dsh` 管理
- 本仓库发布源码，并从 `v2.0.6-beta` 开始提供官方 Windows x64 便携 ZIP

## 主要功能

- **沉浸式写作台**：蓝白浅色主题（可切换蓝黑深色）、统一一级导航、可收起侧栏、专注模式、查找替换和未保存状态提示
- **写作统计**：实时显示字数、段落、预计阅读时长和光标位置
- **安全保存**：定时自动保存，切换资料时自动落盘，退出前检查未保存内容
- **故事资料库**：管理大纲、章节、项目写作风格、角色、世界观、战力体系和时间线
- **故事雷达**：汇总章节目标、相关人物、故事状态、摘要和待回收伏笔；AI 调用后展示脱敏的上下文占用与裁剪报告
- **项目概览**：集中展示最近章节、项目准备情况和基于当前数据生成的下一步建议
- **一致性报告**：按中文问题类型和严重级别展示证据、位置与建议，并可从报告页选择章节重新检查
- **安全定位与修复**：对存在唯一正文锚点的问题支持跳转；仅对可安全替换的正文问题开放 AI 修复预览
- **AI 辅助**：通过 `dsh --profile headless` 扩写章节、检查一致性、修复受支持的问题、生成摘要和更新记忆；扩写与续写可自动应用项目级写作风格
- **任务专属上下文**：扩写、检查、修复、摘要和状态更新分别加载所需资料；本地规则优先排列明确相关的角色、世界观和体系，核心与手选体系始终作为必需资料
- **内置更新**：从“帮助”菜单检查 GitHub Release，可安全下载并验证 Windows x64 更新包；支持自动安装的便携版可由独立更新器备份、替换、启动自检并在失败时回滚
- **首次使用告知**：调用 AI 前明确提示可能发送的数据范围和 AI 输出风险
- **整书导出**：导出为 Markdown 或纯文本

## 环境要求

- Python 3.10 或更高版本
- Windows 10/11（`run.bat`）；其他系统可使用 Python 手动启动
- 使用 AI 功能时，需要另行安装并配置 [DeepSeek Harness](https://github.com/deepseek-ai/deepseek-harness)

DeepSeek Harness 当前仍处于开发者预览阶段，可能发生不兼容变更。遇到调用问题时，请先核对 Harness 的最新官方说明和命令行参数。

当前命令调用形式已对 `@deepseek-ai/dsh 0.1.0-rc.7` 的公开 CLI 帮助完成兼容检查；由于真实生成需要用户自己的凭据和额度，仓库测试不会发起真实 API 请求。

## Windows 启动

下载或克隆仓库后，双击：

```bat
run.bat
```

脚本会创建项目专用的 `.venv` 环境并安装 `requirements.txt` 中声明的依赖。它不会安装 DeepSeek Harness，也不会读取或写入 API 密钥。

## 手动启动

```bash
python -m venv .venv
```

Windows：

```bat
.venv\Scripts\activate
python -m pip install -r requirements.txt
python main.py
```

macOS/Linux：

```bash
source .venv/bin/activate
python -m pip install -r requirements.txt
python main.py
```

## Windows 打包

从 `v2.0.6-beta` 开始，项目提供无需预装 Python 的 Windows x64 目录包基线。开发者安装 `requirements-build.txt` 后可运行 `scripts/build_windows.ps1`；脚本会执行全量测试、构建 PyInstaller 包、运行无界面自检，并在 `dist/release` 中生成 ZIP、发布清单和 SHA-256 文件。详细边界见 `PACKAGING.md`。

## 配置 DeepSeek Harness

Novalist 将本机设置保存在当前用户的应用数据目录中：Windows 为 `%APPDATA%\Novalist\config.json`，macOS 为 `~/Library/Application Support/Novalist/config.json`，Linux 为 `$XDG_CONFIG_HOME/Novalist/config.json`（未设置时使用 `~/.config/Novalist/config.json`）。

从旧版本升级时，如果新位置尚无配置，Novalist 会读取程序目录中的旧 `config.json`，将规范化后的设置复制到新位置，并保留旧文件作为备份。`config.example.json` 仅作为配置格式参考，不应写入 API 密钥或提交个人配置。

未来的更新下载缓存预留在本机缓存目录中；Windows 对应 `%LOCALAPPDATA%\Novalist\updates`。缓存不包含小说项目，删除后可重新下载。

“帮助 → 检查更新”会读取 `xiauho/novalist` 的公开 GitHub Release。设置中可自愿开启启动检查；开启后最多每 24 小时检查一次。从 `v2.0.7-beta` 开始，发现新版本后可将唯一匹配的 Windows x64 软件包下载到 `%LOCALAPPDATA%\Novalist\updates`，并核对 GitHub 摘要、发布清单、文件大小、SHA-256、包内路径、版本和全部 ZIP 文件 CRC。

`v2.0.8-beta` 便携包增加独立的 `NovalistUpdater.exe` 和逐文件 `package-files.json`。用户确认安装后，主程序只把当前安装中通过受管文件校验的更新器复制到缓存并退出；更新器再次验证缓存状态、ZIP、软件包清单和逐文件哈希，只备份及替换清单内的程序文件，保留项目和其他非受管内容。新版必须通过 `Novalist.exe --self-test` 才会启动，否则恢复旧版本。自动安装仅支持可写的 Windows x64 便携目录，不申请管理员权限，无法满足条件时仍保留手动解压方案。由于 `v2.0.7-beta` 本身没有独立更新器，从该版本升级到 `v2.0.8-beta` 仍需手动安装；安装 `v2.0.8-beta` 后才能自动安装后续兼容版本。

Novalist 的 AI 配置只针对 DeepSeek Harness 的 `dsh --profile headless` 入口，不提供其他模型供应商、API Key 或模型列表配置。凭据和模型连接由 Harness 自己管理。

如果系统已经能直接执行 `dsh`，保持默认设置即可：

```json
{
  "config_schema_version": 5,
  "dsh_command": "dsh",
  "dsh_launcher_args": [],
  "dsh_profile": "headless",
  "dsh_timeout": 600,
  "dsh_extra_args": [],
  "ai_model_context_window_tokens": 0,
  "ai_context_strategy": "balanced",
  "ai_history_mode": "auto",
  "ai_context_history_chapters": 5,
  "ai_history_remote_enabled": true,
  "dsh_file_prompt_budget": 20424,
  "dsh_task_file_max_bytes": 512000,
  "ai_input_token_budget": 24000,
  "ai_runtime_reserve_tokens": 6000,
  "ai_chunk_token_budget": 5000,
  "ai_chunk_overlap_tokens": 300
}
```

Novalist 使用固定的双平面传输：`argv` 只携带短小的任务文件加载指令，完整的系统
约束和用户任务统一写入隔离目录中的临时 UTF-8 文件。应用会先验证 Harness 的文件
读取能力，并要求返回文件头、正文中部和文件尾三个随机校验值；回执错误或文件能力
不可用时任务会安全停止，不会把业务提示词降级到命令行。任务文件在成功、失败、
超时或取消后都会尽力删除。`dsh_task_file_max_bytes` 是独立的传输安全上限，不代表
模型上下文容量。配置 schema v3 会删除旧的 `dsh_prompt_transport` 开关，并将输入
token、字符和任务文件上限改为由模型窗口与使用策略统一派生。

配置 schema v4 增加 AI 扩写前文参考模式。新配置默认自动参考：兼容优先最近 3 章、
均衡 5 章、深度 8 章。自定义模式可选择最近 0～200 章，0 表示不携带历史章节摘要
（本章规划、故事状态和设定仍按任务规则提供）。旧配置中的参考章数迁移为自定义值，
包括原来的 0 章，不会被自动模式覆盖。

历史摘要分别受业务输入 token 预算的 15% / 20% / 25% 上限及全局剩余空间限制。
先保留本章任务、核心设定、人物和状态，再优先选择较近章节的完整摘要条目；不对合并后
的摘要字符串截尾，也不为填满空间而加入不相关的章节。最近范围内缺少摘要时，
上下文报告会显示缺失数量并提示更新故事记忆，不会在扩写过程中自动生成摘要。
报告同时记录实际纳入数、预算排除数和历史 token 用量。

配置 schema v5 增加扩写的“补充更早相关剧情”开关，默认启用；自定义参考 0 章时，
近期摘要和远期检索均关闭。远期检索扫描目标章之前、近期范围之外的已采用章节记忆，
不受最近 200 章的范围限制。按人物/地点名称、别名和关键词本地排序，最多选取 20 个
版本有效的相关章节，每章最多 6 条相关事实，再与近期摘要共享上述预算；近期摘要优先。
检索不调用模型，不自动生成摘要，也不承诺语义搜索的召回率。续写和一致性检查的提示词
同样使用可追溯历史选择器，但保留各自的近期章数；设置页的章数仅用于扩写，远期参考
开关同时控制扩写和一致性检查。
修复、记忆更新不增加远期摘要输入。

只有用户明确采用记忆提案后，才在项目的 `memory/accepted_chapter_memory.json`
保存摘要版本、章节正文哈希、结构化事实及段落证据、状态快照和依赖哈希。该文件是
版本化的可携带项目数据，不是可随意清除的缓存。候选提案不会进入检索；正文或摘要
变化、章节删除、记录校验失败时，相应记录不再参与检索。旧摘要不自动补造来源：
仍可作为带“版本未确认”标记的近期参考，重新更新并采用记忆后才可参与远期检索。
这些校验只能确认来源和版本，不能证明 AI 摘要的事实正确性，仍须作者审核。

扩写、续写与一致性检查优先使用目标章节之前且依赖未变化的已采用状态快照；无法确认
时省略该状态，避免把后续章节的累积状态当作前文。旧项目仅在状态章号早于目标章时
兼容使用并标记未验证。无法解析章节顺序时不做远期检索。此隔离针对历史记忆，不改变
用户显式提供的设定、主线和未来规划。上下文报告展示来源章节、版本哈希、事实 ID、
命中类型和过期排除数量，不记录检索词或正文；来源证据可在上述项目记录中核对。

Novalist 还会用本地保守估算器计算每次 AI 输入的预计 token。超出配置上限的任务
会在创建任务文件和调用模型前停止；该数字用于硬准入、分块和诊断，并不等同于模型
供应商的精确 tokenizer 或计费结果。模型窗口未确认时使用 24000 token 输入和
6000 token 运行预留；在设置中声明 128K、256K、512K、1M 或自定义窗口后，应用按
“兼容/均衡/深度”策略自动派生业务输入、保守字符预算和任务文件上限。模型窗口是
输入、输出及 Harness 运行上下文的总容量，输入与运行预留之和不得超过它。章节事实账本的
基础层按段落边界分块，默认每块 5000 token、相邻块最多重叠 300 token；分块
结果经过章节 ID、分块 ID、正文哈希和段落锚点校验后，作为可重建缓存保存在系统
应用缓存目录。缓存不保存原始章节分块，但会包含由其派生的局部摘要和事实。

记忆更新统一使用事实账本/Patch 流程：先从分块事实归并章节摘要，再生成带事实依据和
`expected_before` 前置条件的白名单状态 Patch。应用会在本地检查字段碰撞、过期状态、
缺失依据和推断性更新；存在阻断冲突时不会写入项目。长事实账本会按 token 预算进行
多级归并，归并后不再重复发送原始章节正文。旧版整对象状态生成流程已移除。

设定上下文统一使用本地安全筛选：只通过确定性的标题、
Markdown 小标题、别名、标签和角色名称匹配，不会为筛选额外调用模型或联网；
相关条目优先进入分类容量；没有任何明确匹配时仅保留少量确定性背景回退，不会用
未匹配资料填满扩展后的模型窗口。全局核心规则、标记为
核心的体系和作者本次手动选择的体系不参与普通背景竞争。不再提供整体加载全部
候选设定的运行模式。

## 项目数据迁移

新项目会在 `.novalist/project.json` 中记录独立的项目格式版本；配置文件使用
`config_schema_version`，两者均不与应用发布版本混用。打开没有格式清单的旧项目时，
Novalist 会先检查 JSON 数据和可写空间，再把受影响文件备份到
`.novalist/backups/migration-*`，通过原子写入完成伏笔、体系注册表、核心规则和风格指南
迁移，最后才更新项目格式版本。迁移失败会自动恢复；若上一次迁移意外中断，下次打开
会先根据本地迁移日志恢复。比当前程序更新的项目格式会被明确拒绝，不会尝试降级。

旧故事状态中的伏笔字符串迁移到 `memory/foreshadowing.json` 后，会从活动故事状态中
移除；原值仍保留在迁移前备份中。章节正文和其他作者 Markdown 不参与内容重写。
AI 事实账本和记忆提案属于可重建缓存，协议版本不匹配时直接失效重建。

也可以通过官方 npm 包运行。在 Windows 的“偏好设置”中将命令设为 `npx.cmd`，启动参数设为 `--yes @deepseek-ai/dsh`；对应 JSON 为：

```json
{
  "dsh_command": "npx.cmd",
  "dsh_launcher_args": ["--yes", "@deepseek-ai/dsh"],
  "dsh_profile": "headless"
}
```

macOS/Linux 通常使用 `npx` 而不是 `npx.cmd`。API 密钥应按照 Harness 官方文档配置，不要写入 Novalist 配置、源码或 Git 提交。

## 基本使用

1. 启动后打开 `projects/demo_novel`，或新建自己的项目。
2. 从左侧打开章节，在中间编辑器中写作。
3. 使用“AI 扩写”“检查设定”或“更新记忆”时，首次调用会显示数据处理告知；调用期间可在右侧“上下文”页查看实际传输方式、预算占用和各类资料的保留或裁剪情况；检查报告页可直接选择其他章节运行检查。
4. 一致性问题只有在正文原句能够唯一定位且适合安全替换时才开放“AI 修复”；修复结果必须经过预览确认，且不会自动保存章节。
5. 审核 AI 输出后再保存、采用或公开。
6. 通过“文件 → 导出全书”生成 `.md` 或 `.txt` 文件。

## 数据与 AI 输出说明

Novalist 本身不提供云服务或遥测。普通编辑内容保存在用户选择的本地项目目录中。

当用户主动调用 AI 功能时，当前章节以及完成任务所需的大纲、写作风格指南、角色、世界观、摘要和故事状态可能被传递给本机配置的 `dsh`，并由其连接的 AI 服务处理。请勿提交无权处理的作品、商业秘密或敏感个人信息。

`dsh` 在 Novalist 创建的隔离临时目录中运行，不能直接读取或修改项目文件；命令行仅接收短加载指令，系统约束、章节与设定等业务数据统一通过临时任务文件传入。上下文先按重要性裁剪（优先保留章节大纲、正文结尾与故事状态），最终提示词仍超过 token 或文件字节硬上限时会在调用模型前停止。

每次 AI 调用还会在右侧“上下文”页生成一份仅驻留于当前应用会话的脱敏报告，记录任务类型、字符预算、实际传输方式、各上下文分区的原始长度与发送长度、裁剪状态以及临时文件清理结果。报告还会按资料类别显示候选、明确相关、预选、最终纳入、未匹配排除、分类容量排除和总预算排除数量，并列出“全局核心”“手动选择”“标题命中”等选择原因。扩写纠偏重试、伏笔复核、事实提取和记忆 Patch 等多次调用会分别列出。若 Harness 未按正文协议返回标记而触发纯正文兼容回退，AI 输出区会明确显示本次次数和当前应用会话累计次数。报告与诊断不包含章节正文、设定原文、完整提示词、凭据、资料文件名或绝对路径。

AI 输出可能存在事实错误、遗漏、不当内容或与第三方作品相似的表达。用户应在采用、发布或商业使用前自行审核。更完整的说明见 [PRIVACY.md](PRIVACY.md)。
