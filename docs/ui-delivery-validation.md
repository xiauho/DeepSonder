# UI 细化与本地交付验收

本轮按“真实阅读位置 → 整体交付检查 → 紧凑设置 → 长段落性能”的顺序推进。所有项目、配置迁移和冲突模拟使用临时数据；只生成本地包，不发布到远端。

## 输入性能

`scripts/benchmark_prose.py` 使用完整 MainWindow、1440×900 窗口、18px 正文和 1.8 倍行距。每种形态先预热一次，再在正文中间插入一个字符，记录同步应用信号和 `processEvents()` 返回前的耗时，随后撤销。磁盘原文与加载修订始终不变。

同机 Windows 10、Python 3.12.10、PySide6 6.8.3、离屏模式，9 次样本的中位数如下。比较数据均未启用性能分析器。

| 字符数 | 形态 | 优化前 / ms | 优化后 / ms |
| --- | --- | ---: | ---: |
| 3,000 | 常规分段 | 2.0 | 2.1 |
| 3,000 | 单段落 | 4.3 | 4.3 |
| 30,000 | 常规分段 | 6.5 | 6.8 |
| 30,000 | 单段落 | 18.0 | 13.9 |
| 200,000 | 常规分段 | 36.2 | 37.1 |
| 200,000 | 单段落 | 113.4 | 80.9 |

20 万字单段落本次测量减少约 29%。性能分析定位到重复视觉行遍历后，只复用有效显示几何；没有推迟正文同步、保存判断或 AI 来源检查，也没有自动拆段。此测量不包含真实键盘／输入法、屏幕呈现或定时器等待，不能当作所有机器上的延迟承诺。超长文本仍有全文解析与同步成本。

## 可执行程序自检

保留 `--self-test` 资源检查，增加显式诊断入口 `--ui-self-test <报告路径>`。诊断使用离屏窗口及独立临时目录，不读取普通用户配置、不打开个人项目、不调用模型；仅在全部成功后写入不含正文的 JSON 报告。

整窗自检覆盖新配置默认值、旧配置迁移幂等、真实正文位置恢复、设置保存应用、AI 候选结果保留待审且不自动落盘、外部修改冲突保留文件和作者草稿。构建脚本在压缩前对实际可执行程序运行两类自检；整窗报告保留在 `build/pyinstaller-pyside6/ui-self-test.json`，不随用户包分发。

## 验收记录与限制

全量回归通过：141 个模块、1237 项测试，10 项按既有条件跳过，0 失败。最终诊断模块位于 UI 层，调整模块路径后单独复验 6 项运行资源／入口测试，全部通过。行距安全测试增至 17 项，排版配置与设置测试 16 项，真实阅读位置测试 9 项。

布局矩阵在浅／深色、1100／1440／1600px、普通／放大界面字号和 1.25／1.5／2 倍缩放下通过，共 432 组正文布局、144 组设置预览。检查排版控件无需滚动可达、预览收放保持草稿、正文选区与修订不变、无横向溢出及把手不覆盖正文／滚动条；正文修改信号和保存信号均为 0。

本轮日志、性能原始样本、主题与缩放截图位于本地忽略目录 `output/ui-implementation-final-20261030/`。构建采用干净的本地提交，ZIP 校验值和对应源码提交记录在 `dist/release-pyside6/`。

**真实 Windows 输入法候选窗仍待补验。** 原生电脑工具运行时初始化和重启重试均遇到 `helper_unknown_error: setup refresh had errors`，尚未进入系统输入路径。合成组合、提交、取消、重载以及排版变化已有自动测试；这些不能替代系统候选窗验证。
