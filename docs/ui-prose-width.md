# UI 细化第三步：可调整正文行宽

本阶段接续保存反馈统一，实现正文行宽的拖动、数值调整及跨会话恢复。字号与行距设置仍按后续阶段处理。

## 使用流程

在“视图 → 正文行宽”或文档工具栏“更多 → 正文行宽”选择：

| 模式 | 行为 |
| --- | --- |
| 推荐 | 按当前正文字体计算舒适行宽，默认使用此模式。 |
| 自定义 | 使用上次设置的宽度，首次为 760px。 |
| 铺满 | 使用当前可用区域，保留上次自定义数值供切回。 |

“设置正文行宽…”接受 480–1600px 的文字区域宽度；“恢复推荐正文行宽”回到推荐模式。窗口变窄或参考面板打开时，显示宽度自动适应空间，不改写偏好；重新获得空间后恢复设定宽度。数值采用界面的逻辑像素，显示缩放由 Qt 处理。

正文左右留白中各有一条把手。向内或向外拖动后切换到自定义模式，正文保持居中；未达到横向拖动阈值时不会开始调整。单击把手可以输入数值。

键盘可用 Tab 聚焦把手，Enter／空格打开数值输入，左右方向键调整对应边界，每次改变行宽 16px，Shift 加速至 64px；Home 恢复推荐。拖动过程中 Esc 先取消本次调整并恢复先前模式及数值，不同时退出专注模式。离开页面、失去鼠标捕获或窗口失活也取消未完成的拖动。

鼠标调整不夺取原输入焦点。把手位于原有正文留白内，文字视口和滚动条的操作区域均保持可用。把手的说明提供当前模式、可见宽度和键盘操作。

## 实现和数据边界

- `ui/prose_width.py` 定义偏好校验及鼠标／键盘把手；`ChapterWritingPage` 继续使用原来的 `QPlainTextEdit`，调整布局边距并定位把手。
- 行宽变化单独发出界面信号，不发出正文更改或保存信号；不替换文档，不重建正文控件，不清除撤销，不重置修改标记。
- 宽度与模式存入界面偏好的 `layout.reading_width`，不写入项目、Markdown、设置草稿或 AI 结果。偏好在各章节间通用。
- 旧 `comfortable_width=true/false` 分别恢复为推荐／铺满。新偏好优先；损坏模式回退旧偏好，非整数宽度使用默认值，超界整数限制到允许范围。
- 既有内部舒适行宽开关继续映射推荐／铺满。正式菜单使用三种模式；菜单动作与命令搜索复用同一组 QAction。
- 调整不改变加载修订、待保存草稿、保存错误、设置草稿和 AI 来源。任务或候选不会因显示偏好而自动采用。

## 验证范围

新增 `tests/test_prose_width.py` 的 16 项测试验证两侧真实指针事件、超界拖动、取消及中断、数值取消、键盘入口、窄窗口恢复、跨会话偏好、旧布尔值与损坏偏好，以及正文、反向选区、撤销、修订、保存状态和 AI 来源保护。真实本地任务产生待审结果后，调整行宽仍保留待审并匹配原来源，不写入候选。正文长短变化引起滚动条出现或消失时，单独检查把手不覆盖文字及滚动条。

原有阅读工作区测试继续验证主题、字号、窗口、专注模式、保存及准备摘要，菜单断言更新为三模式子菜单。

本地布局矩阵使用临时长段落章节，在浅／深色主题、1100／1440／1600px 窗口、普通／放大字号以及 125%／150%／200% 缩放下，检查推荐、铺满和 480／900／1600px 自定义宽度，共 180 组通过。检查把手不覆盖文字或滚动条、无横向溢出、原文及选区／修订／历史不变、无正文变更或保存信号。日志与截图位于 `output/ui-implementation-prose-width-20261030/`。

最终全量回归：139 个模块、1208 项测试，10 项按既有条件跳过，0 失败；最终行宽专项 16 项通过，应用资源自检、能力清单与补丁格式检查通过。

本阶段不修改示例或个人项目，不调用模型，不生成安装包。后续接入字号／行距设置与已有用户偏好迁移，再统一完成打包验收。
