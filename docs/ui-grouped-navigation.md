# 入口与任务优化：第二阶段

本阶段延续 2026-10-29 UI 方案，在第一阶段可读列宽与资料密度优化基础上，减少重复导航和任务面板常驻空间。

## 导航入口

- 常用视图为“写作、资料、检查”。章节与资料目录随一级入口切换，不再在目录中重复提供章节／资料页签。
- “检查”保留两个独立页面：“检查报告”和“故事记忆”。离开后再次点击“检查”，回到本次会话最后使用的页签。两页均保留明确的视图菜单及命令搜索入口。
- 左侧“项目”菜单在所有正常页面可用，提供项目概览、新建、打开、旧版导入、最近项目及导出。
- “更多”菜单提供回收站和命令查找；设置仍有固定入口。所有菜单项复用原 QAction 和文档／项目保护流程，不通过新入口绕过保存、运行中任务或待审结果检查。
- 切换工作区通过正常文档路由恢复所选章节、故事规划、结构化资料或时间轴；分别保留目录搜索、选择、展开及滚动状态。显式快速打开或“定位当前”继续清除遮挡目标的过滤条件。

工作区自动恢复仅使用当前项目目录清单中的条目。若所选文件已移除，回退到同工作区中仍存在的文档；没有文档时显示新建提示。恢复不写入正文或资料，也不自动采用 AI 结果。

## 紧凑 AI 任务

任务面板默认显示状态、目标、当前进度及取消或待审阅操作，并按内容和字号计算紧凑高度。待审阅时，“审阅结果”和“放弃结果”直接可见，仍需进入既有审阅流程和明确写入确认。

“详情”提供本次上下文、检查报告及工作记录入口。展开记录时恢复可调整高度，收起详情后回到紧凑显示；收起或清空工作记录均不会放弃候选结果。失败原因和阶段进度仍在摘要区可见，不要求展开日志才能知道任务状态。

新任务默认收起详情；任务取消、取消中、失败、待审阅和专注模式继续沿用现有状态机。任务面板被用户关闭后，后台结果不会自动打断写作，状态栏仍保留“待审阅”入口。本阶段未增加永久任务历史、多任务队列或侧栏写入确认。

## 验证

新增 tests/test_grouped_navigation.py 覆盖真实主窗口中的分组入口、菜单复用、页签记忆、章节／规划／资料／时间轴恢复、独立搜索状态、拒绝切页时草稿保护、紧凑详情与日志、待审结果及明暗主题大字号布局。原目录、导航、任务测试随控件结构更新，继续验证实际可见状态和保护行为。

完整回归、150%／200% 缩放与窄窗口截图记录在本地 output/ui-implementation-phase2-20261029/。所有截图与交互预览使用独立临时项目，未初始化或修改仓库项目。

最终结果：135 个模块、1150 项测试，10 项按既有条件跳过，无失败。应用资源自检通过。两档缩放下共 16 组主题／窗口／字号检查通过，包含新增检查页签、运行／待审任务和窄窗口展开详情的截图验证。
