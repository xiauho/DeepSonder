# 人物多身份关联

适用于 DeepSonder-PySide6 当前桌面的故事记忆和角色卡流程。

## 使用

1. 在“创作”菜单选择“人物身份管理…”。先处理正在运行的 AI 任务或待审结果。
2. 输入主要显示名和全部身份名称（每行一个，最多 20 个），选择身份揭露章节，并填写原文依据或作者确认说明。
3. 点击“预览关联与字段冲突”。已有状态不一致时，逐字段选择采用哪个身份的记录；确认后保存。
4. 后续继续正常“更新记忆”。正文使用任何已确认名称，都能读取同一人物的有效状态；更新仍须通过原称呼的事实证据校验和人工采用。
5. 角色卡内容通过“同步角色档案”单独预览和确认写入。身份关联本身不改正文、角色卡或已采用的历史记忆文件。

已有关联可选中后扩展名称或更改显示名，人物 ID 保持不变。扩展时保留全部已有名称，并明确选择本次关联适用的揭露章节。选择“撤销所选身份关联”可恢复各称呼分开显示；已写入的角色卡文字不会随撤销自动回退。

## 数据与边界

- 关联保存在项目内 `memory/character_identities.json`，包含固定 ID、名称、揭露章节、确认依据、字段选择及操作记录。
- 原始状态仍按事实中的称呼保存。统一状态是一层读取视图，避免破坏性合并后无法恢复。新采用的更新使用本地递增版本接续字段；人物关系端点统一解析。
- 已有冲突由作者选择，不根据名字相似、处理顺序或 AI 推测静默合并。同名冒充、可传承称号不应直接关联成同一人物。
- 记忆生成从所选揭露章起使用关联；较早章不使用该关联。写作上下文中的历史状态按章前范围解析。作者自行写入角色卡的秘密仍属于显式提供的设定，本功能不自动删改角色卡内容。
- 后续字段更新依赖章节原有记忆流程和证据检查，不声称理解倒叙、梦境或所有剧情时间关系。关系字段整体存在冲突时需选择来源，端点归一后有不同关系标签则保留“待核对”提示。
- 更改关联会改变状态及任务上下文签名，旧记忆提案不能直接采用，相关资料检索缓存会重新计算。角色卡旧同步预览也会阻断。
- 撤销后保留关联期间按各原称呼写入的更新。历史摘要与正文不重写；如需要新的摘要，显式重跑相应章节的记忆更新。
- 本阶段提供人工关联；AI 自动提出身份揭露候选、每个身份独立的职业/阵营时间线，以及独立 schema-v2 知识重建服务的身份模型统一，均未包含在本次改动中。

## 验证

新增测试覆盖多个身份、固定 ID、字段冲突、揭露章节隔离、交替更新、物品删除、证据拒绝、同目标冲突、角色卡去重/同步、关系图、缓存、旧提案失效、撤销和原始文件保护。界面验证覆盖窄窗口、浅色/深色主题与 150% 显示缩放。
