# 记忆更新优化与验证

适用范围：本仓库 DeepSonder-PySide6 桌面的“更新故事记忆”。

- 任务面板显示准备章节、提取事实 i/n、合并事实、准备资料、归并事实 i/n、生成提案、校验提案；每秒更新任务已用时间。完成阶段耗时及缓存命中写入工作记录。取消和待审阅状态不会被迟到的进度覆盖。
- “本次上下文”的脱敏报告新增 invocation_ms、probe_ms、generation_ms、retry_ms、output_chars。生成耗时包含 DSh 启动、读取提示词和模型执行，不能当作纯模型推理耗时。总调用耗时包含清理；阶段时长可能嵌套，不可与调用耗时直接相加。失败和取消也记录已执行请求的耗时。
- 默认 5,000 token 分块策略下，若整章能装入 min(8,000, 输入预算/2) token 且完整事实提示词通过预算检查（现已直接计入完整任务文件包装及消息预留），使用一个分块。长章节、用户自定义分块预算仍使用原策略；不截断正文。8,000 为保守初始阈值，尚无真实模型质量基准证明更大的分块更好。
- 事实提示词要求简洁表达和消除同义重复，但明确保留独立事实、时间变化、矛盾及位置证据；没有新增硬性事实条数裁剪。
- 事实提示词版本由 2 升至 3，提案版本由 5 升至 6；旧派生缓存不再复用，首次生成可能重新提取。已采用记忆及项目源文件不迁移、不修改。新缓存重复运行仍可免 AI 调用。

## 验证与后续

使用临时项目、合成文本和模拟模型验证调用数、锚点、取消、缓存、无写入和诊断脱敏。真实 DSh 延迟及事实召回率需以代表性章节测量；不据模拟测试宣称百分比提速。建议比较短章、中章、长章、密集人物移动章节：首次/重复/编辑后运行的总耗时、阶段耗时、请求数、重试数，以及人工检查的事实遗漏和错误 Patch。

后续按实测结果决定是否默认启用并发 2；稳定分块缓存及持久传输尚未实施。本阶段保持事实提取与提案分离、证据校验、过期上下文检测和显式采用确认。

## 预算与归并前置优化（2026-10-02）

- 记忆的事实、归并、提案组装与 DSh 发送共用任务文件估算器，计算实际文件包装、nonce 检查点和消息预留。可用输入空间同时受模型窗口与运行预留约束。普通章节也会先检查全部分块，超限时进一步拆分，不截断正文。
- 归并前检查已选入的相关设定、章前状态和固定协议所需空间；必要资料不能装入时立即报错，避免追加无效归并。取消原来的 12,000 字符设定切片及归并后的设定/人物二次削减，沿用既有相关资料选择与状态展示规则。
- 归并批次按含传输包装的剩余空间打包，所有批次先检查后调用。每条输入事实 ID 必须保留引用；缺少证据不接受、不缓存。来源变大或连续两轮压缩不足 5% 且仍超预算时停止重复调用；最多 10 轮的兜底仍保留。这些检查保护证据覆盖，不代替人工语义审阅。
- 设置 → AI 与连接新增“整次记忆更新等待上限”，默认 1,800 秒，可设 30–7,200 秒；原有 600 秒为单次请求等待上限。事实、归并、提案、文件探测及回执重试共同使用本次剩余时间。上限针对后台生成，不包含人工审阅；本地处理在检查点判断，取消/超时后的进程清理仍需有限时间。
- 超时或取消后的迟到响应不进入缓存或审阅。此前已校验的事实缓存保留，下次重新发起可复用；第一批未新增逐批归并检查点；第二批已补齐，第三批已提供可选的两路并发，默认仍为串行。
- 工作记录新增任务汇总、阶段耗时、归并输入/输出估算和证据数，以及缓存复用/未匹配/主动刷新原因。逐请求脱敏报告带运行 ID、请求序号及块/归并批次标识；首次探测和回执重试分开计数，不包含正文、事实文本、nonce 或凭据。
- 提案提示词版本升至 7，旧提案与归并派生缓存不复用；事实提示词版本仍为 3，合法且分块一致的事实缓存继续复用。已有采用记录、正文、项目格式和显式写入保护不迁移。

对应分析与验收路线见 [记忆更新耗时分析与优化方案](memory-performance-analysis.md)。本批使用临时项目、模拟模型、预算边界、固定资料溢出、证据遗漏、非收敛、超时恢复及界面状态测试验证；未调用真实模型，不宣称固定比例提速。

最终验证：`scripts/run_tests.py` 完成 104 个模块、706 项用例，失败模块 0，2 项 Windows 原生标题栏用例因离屏环境跳过。`git diff --check` 通过。设置及任务状态覆盖窄桌面宽度、浅/深主题、较大字号；设置页另以中文字体、760 像素逻辑宽度和 150% 显示缩放进行截图检查，无横向滚动或字段截断。

## 逐批检查点与紧凑事实传输（2026-10-02，第二步）

- 每批归并在解析、短引用还原、全部来源证据覆盖以及取消/整次时限检查通过后，原子保存一个检查点。后续批次失败、取消或超时不删除此前完成的批次；重新发起任务会校验并复用它们，仅请求缺失批次。已完成的所有批次也可在整体归并缓存不可用时重建该缓存，无需重新调用归并模型。
- 检查点键包含原始输入及顺序、完整事实 ID、锚点、章节来源、实际提示、传输/提示版本，以及应用已捕获的 DSh 命令、启动参数、profile、extra_args、context_strategy 指纹；参数只参与哈希，不明文写入。加载时复核结果哈希、结构、当前允许引用和证据覆盖。损坏或不匹配视为未命中。仅改变章前状态或相关设定，可复用相同事实的批次，最终提案仍使用新资料。DSh 外部配置文件变化不在已捕获参数内；需要强制刷新时使用“重提事实”，它会跳过事实、批次、整体归并和提案缓存。
- 传输版本 1 使用请求内的 f1、f2 等短引用，事实行依次为 `[引用,类别,主体,谓词,值,正文锚点,确定性]`，分块摘要和未解决问题也采用有明确列顺序的紧凑行。所有事实及字段、完整文本值、锚点顺序和未解决问题均保留，无硬裁剪。本地事实账本、归并检查点、审阅提案和采用记录继续使用完整 ID。
- 响应须原样返回当前输入对应的 wire_request_id；仅 fact_ids/evidence_fact_ids 字段经当前请求映射还原，摘要文本、Patch 值等不做字符串替换。跨请求、未知短引用、使用完整 ID 代替短引用及无效引用结构均拒绝，不缓存、不进入审阅。最终请求 ID、章节/状态/设定过期检查、位置证据校验和显式确认仍保留。
- 批次装箱与收敛诊断改用实际紧凑传输数据估算，模型调用仍先核算完整提示和任务文件包装。新增“批次缓存命中”进度，任务汇总计入复用次数；reduction_calls 只计本次实际发起的归并请求。
- 提案提示词版本 8、提案派生缓存结构版本 2；最终提案缓存还绑定完整账本（含摘要、事实、确定性及未解决问题）和调用配置，避免相同事实 ID 下语义变化仍误用旧提案。旧提案/归并缓存不复用；事实提示词仍为 3，合法事实缓存继续复用。已有用户项目与采用记忆不迁移。

合成样本：100 条事实，完整 ID 为 `fact_` 加 64 位哈希，保留全部地点值及正文锚点。仅事实来源 JSON 从 20,683 字符降至 6,875 字符，保守估算从 11,212 token 降至 5,002 token；不包含提示说明、返回模板和文件包装，真实收益随事实长度变化，不能等同于模型耗时下降比例。中断恢复、取消/超时迟到、缓存损坏、输入/配置失效、强制刷新、多轮映射及不写入项目使用临时项目和模拟模型验证。

第二步完整回归：`scripts/run_tests.py` 完成 105 个模块、723 项用例，失败模块 0；2 项 Windows 原生标题栏用例因离屏环境跳过。新增 17 项检查点及传输测试，`git diff --check` 通过。没有调用真实模型或修改演示/个人项目。

## 有界并发（2026-10-02，第三步）

设置 → AI 与连接新增“记忆任务同时请求数”：默认 `1 · 稳定（默认）`，可选 `2 · 并发试验`；保存后用于下次记忆任务。单块/单批及全部缓存命中时不创建并发客户端。本阶段不自动改变用户现有设置，其他 AI 功能继续沿用原来的执行方式。

- 仅并行当前章节互不依赖的事实块与同一轮归并批次。每轮全部成功后才进入下一轮，全部事实与必要资料准备好后才生成最终提案；前后章节及最终状态写入仍按既有依赖顺序执行。
- 最多两项在途，不把整章任务一次性排入后台队列。两路客户端各自复制捕获的命令、模型参数、预算等配置，拥有独立临时工作目录、探测状态及任务文件；不会同时使用同一个 DSHClient，也不传 resume 会话参数。客户端在任务内复用，最终提案使用已经空闲的一路，避免额外创建第三路及重复探测。
- 主协调线程按完成数量显示进度和提交派生缓存，按输入索引确定性排列事实块与归并片段；模型返回乱序不改变后续输入顺序。每个实际请求获得同一运行 ID 下唯一序号，来源块/轮次/批次标识保留。并行阶段的完成事件记录相邻完成点之间的墙钟间隔，避免把重叠等待直接累加；逐请求耗时仍独立显示。
- 取消、整次时限到期、证据校验失败或一般调用错误后停止提交新任务，通过各路取消信号终止相关进程树，等待所有后台请求退出后再清理临时目录和结束前台任务。迟到成功响应不保存或进入审阅；此前完成的事实与归并检查点保留，重试继续复用。当前任务绑定的诊断通过排队信号展示，旧任务或已取消任务的迟到诊断不能覆盖新任务。
- 只有明确的 HTTP 429/限流、并发容量拒绝或共享索引忙错误会触发串行回退。先停止、等待两路退出，保留已校验成功结果，再对未完成项串行尝试一次；失败继续向用户报告，无无限自动重发。回退后本次任务后续阶段保持串行。其他错误直接停止，保留已完成缓存，由用户决定重试；尚未引入基于故障率或尾部延迟的统计自动切换策略。
- 汇总显示任务结束时的同时请求上限与回退次数；业务请求数含实际失败、取消及串行重试尝试，归并请求数亦计入这类实际归并尝试。缓存命中不增加请求数。创建隔离客户端失败或客户端不支持隔离时安全使用串行，已创建的私有客户端先清理。
- 不改变事实提示词版本 3、提案提示词版本 8、项目格式或采用记录；串行与并发共享相同的合法事实、批次及提案缓存。审阅、显式确认、过期上下文、位置证据校验和原子写入保护继续保留。

本机只读检查的 DSh 安装为 `0.1.2-rc.1`：headless 为每次调用创建随机 UUID 会话，元数据包含工作目录；会话日志路径使用工作目录与会话 ID。仍存在共享的设置/凭据与 SQLite 派生索引，不能仅凭工作目录隔离认定所有插件及服务允许并发。因此两路模式保持试验性质；启用默认并发需要代表性章节的真实模型吞吐、错误率、尾部延迟和事实质量验证。此次不调用模型或改动外部引擎配置。

验证包含：乱序结果与完成计数、最多两路在途、配置快照、任务文件/探测/报告隔离、取消与超时停止排队、限流后不重发成功项、再次限流终止、并发失败后的缓存恢复，以及使用本地 Python 模拟引擎实际启动两个父子进程树并确认取消后全部退出和工作目录清理。该进程测试不会联系模型服务，也不能替代真实 DSh 并发兼容性验证。

第三步完整回归：`scripts/run_tests.py` 完成 106 个模块、741 项用例，失败模块 0；2 项 Windows 原生标题栏用例因离屏环境跳过。新增 16 项并发测试及 2 项设置/诊断测试；`git diff --check` 通过。设置页以中文字体、760 像素逻辑宽度、20 号字号与 150% 显示缩放检查浅/深主题，选项与说明完整可读，无横向滚动。

## 记忆更新失败恢复（2026-09-18）

- 修复“林夜与苏婉｜到达集合地点｜祖师雕塑所在的广场”等联合主体被误判的问题。主体按明确列名匹配，不以姓名子串或匿名群体认定个人到达；否定、计划、命令、回忆和其他角色到达仍阻断。
- 阻断后“定向重试”跳过旧提案并附带目标、校验原因和事实证据。反馈最多 6,000 字符，计入提示词预算，不写入缓存或脱敏上下文报告。每次操作只启动一次流程，无无限自动重试。
- “重提事实”刷新当前章节事实，并跳过归并和提案缓存，不清除其他章节的缓存或已采用记忆。重试启动前检查项目、章节、未保存编辑、正文及故事状态，来源变化则要求重新发起。
- “审阅可用部分”仅在局部阻断可隔离且存在独立更新与事件摘要时出现。排除失败目标以及共享证据的关联更新，再重放剩余更新；事实矛盾、设定冲突、状态前置条件失败等不允许绕过。
- 部分审阅列出排除项，使用保留事件重建标明“部分记忆”的摘要，不沿用原摘要。点击“审阅可用部分”本身不写入，仍须在预览中“确认写入”；取消、过期检查、原子提交及后续章节失效策略沿用现有保护。
