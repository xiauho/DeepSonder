# UI 细化第二步：统一保存反馈

本阶段在第一步行距原型验证之后，落实保存状态的统一呈现。默认字号、行距和行宽功能没有在本阶段改动。

## 日常使用

- 正文、故事规划和结构化资料共用状态栏中的文档保存提示：已保存、未保存、正在保存、保存失败、外部版本变化。
- 页头不再重复显示日常保存状态；保存失败和版本冲突继续在页内显示持续说明和恢复操作。
- 自动保存开关信息放入保存状态的鼠标提示，提示同时提供当前文件和完整错误说明。开关、间隔及触发规则沿用原设置。
- 设置、概览、检查、导出和虚拟时间轴不显示背景文档的保存徽标。设置草稿仍由设置页独立提示与确认。
- 状态栏的一般消息在狭窄空间省略，AI 进度保留自己的消息区域，不覆盖文档保存状态。

正文页发生保存问题后，可重试保存、另存草稿或重新载入。存在外部版本变化时，“处理版本冲突”仍打开原有选择对话框；覆盖磁盘版本必须明确选择。重新载入存在未保存内容时先确认，取消则保留草稿。草稿副本使用独立文件，保留原格式与原文档修订，不清除未保存状态或冲突。

资料页保留原有差异查看、另存草稿和确认后重新载入，并在普通写入失败时提供重试。错误说明和恢复操作移动到页头附近，表单底部的同一错误不重复显示；其他表单操作消息仍可显示。

## 状态来源与安全边界

`ui/save_feedback.py` 提供不可变的显示快照及统一优先级：外部冲突、保存错误、正在保存、未保存、已保存。它不缓存文档内容、不拥有定时保存任务，也不负责写盘或决定写入成功。

正文状态由原编辑器的保存开始、实际成功、异常、载入和草稿变化更新。资料表单在原有 `write_changes()` 外围发出进度状态；原有修订比对、序列化、原子写入和提交后回调保持在原保存路径内。失败重试期间保留未解决的错误，只有成功保存或经确认的重新载入等真实状态变化才能清除。

主窗口收到通知后重新读取当前内容视图的所属编辑器，不把通知中的旧路径或“刚刚保存”消息当成当前文档事实。因此，后台正文保存、旧文件自动保存通知、资料成功提示计时以及 AI 进度均不能将另一文档标成已保存。项目切换、删除、清空和页面切换继续通过原有生命周期处理。

正式主窗口开启嵌入模式，日常状态移至状态栏；独立使用的编辑／资料组件仍可保留自身状态显示。AI 审阅确认、过期来源校验、取消与待审结果保护保持原流程。

## 验证

`tests/test_save_feedback.py` 使用临时项目验证真实写盘、自动保存失败与恢复、明确覆盖确认、草稿副本、重新载入确认、迟到通知、后台编辑器与当前资料隔离、资料错误／冲突、旧成功计时及设置草稿独立性；同时检查窄窗口和大字体下的恢复操作。

`tests/test_workspace_persistence.py` 中的日常状态断言改为检查状态栏，继续覆盖真实保存失败在输入后持续显示。

完整回归、缩放矩阵和实际截图保存在本地忽略目录 `output/ui-implementation-save-feedback-20261030/`。预览仅创建临时项目；不修改示例或个人作品，不调用模型。

全量回归结果：138 个模块、1191 项测试，10 项按既有条件跳过，0 失败；其后补充的 JSON 草稿副本用例与全部保存反馈专项用例共同复验，最终 13 项通过。125%／150%／200% 缩放下，两种主题、三种窗口宽度、两种界面字号、正文／资料两类页面及四种状态，共 288 组布局检查通过。应用资源自检、能力清单与补丁格式检查通过。

本阶段不构建安装包。后续按计划实施可拖动正文行宽，再接入字号／行距设置与偏好迁移。
